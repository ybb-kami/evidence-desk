# 版本证据核对

在工作台首页的「版本差异与可恢复归档」选择两份已导入的 PDF，再打开「核对两个版本的摘要与原文段落」。页面也接受已归档的原件，可关闭本机 E5 后重跑。核对过程只读原件索引，匹配结果和用户选择不会写入文库。

- **作品标识** 摘录可在首页回查的 arXiv 版次印记或 DOI。相同标识、不同标识、标识冲突和待核实分别显示。无标识时，由人工核对作品关系。
- **标题与摘要** 使用首页可定位标题和明确摘要标题下第一段可读摘录。显示措辞变化和本机 E5 双向平均余弦。
- **局部段落** 在前三个物理页的正文小节起始后，每侧取前五条符合条件的原文摘录，每条最多 360 字符。先匹配规范化后一致的措辞。其余段落仅在 E5 分数和双向排名满足条件时列为候选。排版改变、段落拆分、缺少文本层或前置材料较长都可能降低覆盖率。
- **证据核验** 每条摘录保留 SHA-256、物理页、块、分段与原文链接。PDF 原页与定位页均使用各自版本的地址。数字差异提示展示原文中出现的不同数字写法，科研结论仍需结合单位和实验条件阅读。

相似候选使用 `multilingual-e5-small` int8 ONNX 在本机 CPU 推理，复用语义检索的运行时与模型锁。前、反两个方向的余弦取均值。局部段落候选的经验门槛为 0.84，要求彼此均为可配对段落中的最高分，且与次高分的差距至少为 0.015。这些分数用于缩小人工核对范围。模型关闭、缺少资产或暂忙时，保留标识、逐边原文和文字匹配。模型资产安装说明见 [语义检索](../semantic/README.md)。

## 复现

在仓库根目录运行。浏览器验收使用已配置的 ONNX Runtime 与 Chromium，并从空的临时文库开始。PDF 目录应含 `1706.03762v1.pdf`、`1706.03762v7.pdf` 与 `N19-1423.pdf`。改名、释义重排和数字变化的两份无标识样本由脚本生成。

```bash
PYTHONPATH=scanpdf python -m unittest version_evidence.test_compare
PYTHONPATH=scanpdf python -m version_evidence.acceptance --pdfs /path/to/contest-pdf
```

浏览器验收从首页导入 PDF，通过版本入口传递两侧 SHA-256，核对两侧原页高亮、归档原件、启用与关闭模型、缺少模型时的响应、桌面与窄屏宽度。脚本输出模型耗时、从按钮触发到显示结果的用时，以及每组对照的作品标识状态与摘录坐标。

2026 年 11 月 18 日用 Chromium、1280 px 桌面和 390 px 窄屏运行结果如下。耗时包括浏览器请求与结果显示，另行点击原页的时间未计入。

| 场景 | 作品标识 | 摘要余弦 | 浏览器耗时范围 |
| --- | --- | ---: | ---: |
| Attention v1 与 v7 | 共同 arXiv `1706.03762` | 0.960 | 4.51–6.30 秒，初次载入模型 |
| Attention v1 与 BERT | 关系待核实 | 0.822 | 1.38–3.17 秒 |
| 无标识，改名、释义重排 | 关系待核实 | 0.887 | 0.31–1.19 秒 |
| 已归档的 Attention v1 与 v7，关闭 E5 | 共同 arXiv `1706.03762` | — | 0.08–0.12 秒 |

无标识测试的两组释义候选得分为 0.893 和 0.907，另有一段文字一致但块号不同。其中一组仍明确显示左侧 20、右侧 30 的数字差异，两侧高亮分别位于物理页 1 块 5 和块 6。另启一个指向不存在权重目录的服务，确认缺模型时保留原文与文字匹配。
